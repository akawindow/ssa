# SRD 基线核对与后续优先级修正

这是第二轮完成后的文献/实现核对，不是新增实验；不改写已有结果。

后续完成情况：[原版Java基线与接入](JAVA_SRD_RESULTS.md)。已找到可复用本机工具链，跑通作者原样工程并完成逐点接口核验；以下差异是当时使用旧Python原型的核对记录，保留作历史说明。

## 原文实际报告了什么

核对用户提供的《Cleaning Time Series under Seasonal and Trend Constraints》PDF 第 16–18 页：

- 第 7.1.2 节：修复 RMSE 比较的是修复后的序列与干净参考序列。
- 第 7.2.2 节及图 8：同时验证下游预测、分类、聚类。因此不能用“原文只评估修复质量”解释我们与论文的差异。
- 下游预测使用 N-Linear；图 8 的数据是 Grid、Insurance、Airline、Telecom、GPS。我们目前是 Tetouan Zone 1 与 Ridge，不是在复现该图。
- 论文的 Clean 是专家修复参考，或合成错误实验中的原观测参考；并非声称每一种原始输入都应被进一步修复。

## 已确认的差异

| 维度 | 作者材料 | 当前工程 |
|---|---|---|
| 实现 | 作者 Java SRD | Python 修复原型，未做数值一致性校准 |
| 参数 | 当前公开 Experiment.java 合成实验 k=6，真实脏数据实验 k=9 | k=3，不能视为照搬论文设置 |
| 序列上下文 | 公开清洗实验使用长序列或完整真实脏序列 | 每次432点，仅3个日周期 |
| 预测模型 | 原文下游案例 N-Linear | 独立 Ridge |
| 预测数据 | 图8的真实错误数据集 | Tetouan单变量、人工注入条件及无额外污染条件 |

参数来源是此次读取的公开代码，不把它自动等同于原论文所有实验参数：
https://github.com/czjthss/SeasonalClean/blob/main/code/src/main/java/Experiment.java

作者 SRD.java 的修复值中位数取排序后的上中位数；当前 NumPy 中位数对偶数个值取中间两数均值。三周期窗口中排除待修复位置后通常只剩两个同相位参考点，不能假定这一差异可以忽略。趋势辅助类、中位数和边界实现也仍需逐项校准。

较低 k 更容易触发修复；短历史使同相位参考更少、边界占比更大。这些是具体的候选原因，但目前没有控制实验确认它们对预测误差各贡献多少。不能把结果直接归因于 SRD 无效，也不能确定就是误修真实变化。

## 对现有结果的正确表述

人工污染条件下，单独修复原型使验证预测 RMSE 从2461.02降至2155.98，实际存在改善。无额外污染条件下，从2102.49升至2264.75。

以上证明的是当前原型在当前设置中的行为；不代表复现了论文成绩，也不证明原版SRD在无污染数据上必然变差。现有SSA串联的微小增量也需要在可信基线上重新检验。

## 修正下一步顺序

第二轮结束时计划先比较 SSA 权重初始化；核对之后改为**先校准 SRD 基线**，暂缓选择器改动。

1. 对齐作者版本、辅助中位数、趋势提取、边界及修复规则，保存对齐用例和逐点输出；不得依据测试成绩调整。
2. 用作者提供的配对干净/脏数据或一致的合成污染，先验证修复 RMSE 改善，并检查正常点改动情况。
3. 将离线长序列修复与实际预测场景中的历史窗口修复明确区分，评价时只允许使用预测时刻已观测的历史。
4. 在训练/验证集比较 k=3 与作者代码对应设置等预先声明条件；不能根据结果反向宣称某个参数一定最好。
5. 基线可靠后，再检验 SSA 插件是否提供增量。初始化对照保留为后续设想，尚未执行。
